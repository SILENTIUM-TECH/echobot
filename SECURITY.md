# Security policy

← [Back to README](README.md)

## Supported versions

| Version | Status |
|---|---|
| **v10** (current) | Supported |
| Older builds | No longer maintained |

Echo is hosted, so everyone is always on the latest version. WhatsApp changes and security fixes are patched within 24 to 48 hours.

## Report a vulnerability

Please tell us privately before sharing it publicly, so it can be fixed first.

- **Telegram:** [@devaura_echobot](https://t.me/devaura_echobot) or [t.me/loner_01verified](https://t.me/loner_01verified). Start your message with `[SECURITY]`.
- Fallback: the [community group](https://t.me/silentiumXgroup) (say it's a security matter and ask for a private chat).

Please don't open a public GitHub issue for a vulnerability.

**Include:** what it is and where, how to reproduce it, who it affects, and how to reach you.

## What to expect

| Stage | Timeline |
|---|---|
| Acknowledgement | Within 48 hours |
| First assessment | Within 5 business days |
| Fix | Based on severity; critical issues first |
| Disclosure | Agreed with you once the fix is live |

## In scope

- Access to another person's session or stored data
- Using owner or admin commands without the right rank
- Making Echo run code or commands it shouldn't (injection)
- Reading messages or metadata a user hasn't shared

## Out of scope

- Reports with no demonstrated impact, and automated scanner output
- Social engineering of Echo's maintainers
- Issues in third-party services (report those to the service)
- Denial of service through sheer volume

## Safe harbour

If you report in good faith and keep to this policy (no data theft, no harm to users), we won't take action against you, and we'll credit you if you'd like.
